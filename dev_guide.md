# Посібник розробника

Цей документ описує підготовку середовища, запуск UI та API тестів і розташування основних файлів проєкту.

## Вимоги

- Python 3.12 або сумісна версія Python 3.
- Google Chrome для UI тестів.

Для керування Chrome використовується Selenium. Selenium Manager автоматично підбирає драйвер браузера під час запуску.

## Підготовка середовища

Команди нижче призначені для підготовки віртуального середовища з папки проекту:

```
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск тестів

Запустіть усі UI та API тести з кореня проєкту:

```
python -m pytest tests/ --url "адреса тестового середовища" --self-contained-html --html=reports/report.html -n 4 --headless
```

Параметри команди:

| Параметр | Призначення |
| --- | --- |
| `tests/` | Запускає тести з каталогу `tests`. |
| `--url` | Обов’язкова адреса тестового середовища. |
| `--self-contained-html` | Вбудовує ресурси у HTML-звіт, щоб його можна було відкрити окремим файлом. |
| `--html=reports/report.html` | Створює HTML-звіт за вказаним шляхом; попередній звіт із такою назвою буде замінено. |
| `-n 4` | Запускає тести паралельно у чотирьох процесах (pytest-xdist). |
| `--headless` | Запускає Chrome без графічного вікна. Без цього параметра Chrome запускається у звичайному режимі. |

Звіти та логи:

- HTML-звіт: `reports/report.html`
- Лог pytest: `logs/pytest.log`

### Інші варіанти запуску

Запустити тести послідовно, без headless-режиму:

```
python -m pytest tests/ --url "адреса тестового середовища" --self-contained-html --html=reports/report.html
```

Запустити лише UI або API тести:

```
python -m pytest tests/ui/ --url "адреса тестового середовища" --headless
python -m pytest tests/api/ --url "адреса тестового середовища"
```

Запустити один тестовий файл:

```
python -m pytest tests/ui/test_tm_cart_001.py --url "адреса тестового середовища" --headless
```

Для створення HTML-звіту в будь-якому з цих варіантів додайте `--self-contained-html --html=reports/report.html`.

## Структура проєкту

| Шлях | Призначення |
| --- | --- |
| `core/api/` | API-клієнт, моделі даних і сервіси для роботи з каталогом, кошиком та замовленнями. |
| `core/ui/` | Обгортка браузера, UI-елементи та Page Object-и. |
| `tests/api/` | API автоматизовані тести. |
| `tests/ui/` | UI автоматизовані тести. |
| `tests/conftest.py` | Загальні pytest fixtures, `--url`, `--headless` та API-клієнт. |
| `tests/ui/conftest.py` | Fixture браузера для UI тестів. |
| `test-cases/` | Опис ручних тест-сценаріїв. |
| `reports/` | HTML-звіти тестового запуску. |
| `logs/` | Логи pytest. |
| `pytest.ini` | Налаштування форматування та рівнів логування. |
| `requirements.txt` | Python-залежності проєкту. |

## Додавання тестів

- Називайте pytest-файли з префіксом `test_`, щоб pytest автоматично їх знаходив.
- UI тести розміщуйте у `tests/ui/`, API тести — у `tests/api/`.
- Для UI тестів використовуйте fixture `browser` і наявні Page Object-и з `core/ui/pages/`.
- Для API тестів використовуйте fixture `api_client` та сервіси з `core/api/services/`.
- Тестам, яким потрібна адреса середовища, передавайте fixture `base_url`; він отримує значення з обов’язкового параметра `--url`.
- За можливості створюйте окремий тест-сценарій у `test-cases/` для нового автоматизованого тесту.
