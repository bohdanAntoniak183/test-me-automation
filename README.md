# test-me-automation

## Короткий план тестування

#### Мета

Визначення обсягу, пріоритетів та ризиків для тестування (UI та API) навчального інтернет-магазину.
Основний акцент робиться на перевірці ключових бізнес-процесів (каталог, кошик, оформлення замовлення, робота з промокодами, доставка).

#### Обсяг тестування

**_Що входить у покриття:_**
* Каталог (пошук товару та відкриття картки товару).
* Кошик, промокоди та доставка (додавання товарів до кошика, видалення товарів із кошика, застосування вірного та невірного промокоду, використання різних типів доставки, перевірка суми разом до оплати).
* Оформлення та замовлення (валідація полів форми для оформлення замовлення, перевірка статусів оплати, пошук оформленого замовлення, перевірка картки замовлення, скасування замовлення, недоступність огляду замовлення для інших середовищ).

**_Що залишається поза покриттям:_**
* Фільтрування та сортування каталогу.
* Обране та порівняння.
* Відгуки.

#### Пріоритети та ризики

| Модуль/Функціонал  | Рівень пріоритету | Рівень ризику |
| ------------- |:--------------:|:--------------:|
| Каталог (пошук товару та відкриття картки товару) | Високий (користувачі часто шукають товар та оглядають його характеристики) | Високий (у разі проблем з пошуком або відкриттям картки товару, система не дасть можливість оформити замовлення) |
| Додавання/видалення товарів до/із кошика, оформлення замовлення, робота з доставкою та промокодами | Високий (основний крок для оформлення замовлення користувачем) | Високий (система не виконує цільову функцію) |
| Ізоляція замовлень для середовища | Високий (користувач має знати, що його замовлення приватне) | Високий (проблема в ізоляції створює вразливість для системи та руйнує безпеку) |
| Пошук та скасування оформленого замовлення | Середній (користувачі не часто скасовують або переглядають оформлене замовлення, але це важлива дія для користувача) | Середній (система не дасть можливість скасувати або переглянути замовлення) |
| Фільтрування та сортування каталогу | Середній (користувачі не часто фільтрують або сортують каталог, але зі збільшенням каталогу потреба функціоналу для користувача збільшується) | Низький (дія не блокує створення нових замовлень, пошук окремого товару може здійснюватись за його назвою) |
| Обране та порівняння | Низький (користувачі рідко додають товар у обране або порівнюють товари) | Низький (дія впливає тільки на окрему сесію системи) |
| Відгуки | Низький (користувачі рідко додають залишають відгуки на окремий товар) | Середній (створення та відображення відгуків може погано відобразитись на веб-сторінці між користувачами) |

## Тест-сценарії

Спроектований список тест-сценаріїв описаний у папці **_/test-cases_**. Кожен тест-сценарій описаний в окремому файлі. Файл тест-сценарію містить ідентифікатор, назву, пріоритет, передумови, тестові дані, описані кроки, та очікувані результати.

## UI та API тести

Автоматизовані тест-сценарії знаходяться у папці **_/tests_**. Вони відповідно розділені папками **_/ui_** та **_/api_**.

Обраний стек: Python, Selenium, pytest, requests.

Запуск тестів та структура репозиторію описані у **_dev_guide.md_**.
